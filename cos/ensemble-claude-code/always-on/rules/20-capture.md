# Capture — the menu scan

Work throws off feedback constantly. A **capture signal** is feedback that passes one test: it would guide future work if recorded, and be lost if not. The test is never run abstractly — run the **menu scan**: if the thing fits at least one slot below, it is a capture signal; write it now.

**The landing menu — eight questions, a closed set:**

1. Does it change where the route stands or where the next pass picks up? → the route's `Handoff.md`.
2. Is it a problem or question surfaced but not handled, within the route's scope? → the route's `Gaps.md`.
3. Is it a wish bigger than the unit you are in? → an aim surface's ripening region, asking **"bigger toward which body?"** — a complaint about the operating shape itself belongs to the shape's own project aim, not to the project you happen to be in.
4. Is it a standing decision or constraint? → the constitution's bounds.
5. Is new work being born right here? → a designation plus its registry line.
6. Is it a tending's check result? → an occurrence record.
7. Would it matter beyond this project? → the shared external brain.
8. What the pass itself did and left → the iteration record, at the stop.

**Scan moments** — run the scan whenever one fires: a user statement (wish, complaint, correction, judgment); a grounding that confirms or refutes; a problem solved; work uncovered mid-pass; something surfaced but not handled; a wish starting to ripen; a null result ("nothing changed" is keep-worthy); a vocabulary lock; friction with the running operating shape itself. Examples forever, never a gate — not finding your situation here never excuses not capturing.

**Capture in the moment, account at the stop.** Write captures live, where they arise — a capture deferred to the stop is at the mercy of the context window. The pass record tallies them when the pass ends.

**The locality law.** When a capture's rightful home is off-host or outside the current project tree, land it first in the tree it arose in, on a maintained, discoverable surface, marked as a **pending port** with its destination named. Port it when the destination is reachable. Never bury it with a closed pass: an invisible pending port is a lost wish.

**The watch law.** A deferral is work put off until some later condition, and that condition is watched agent-side or it is not watched at all. Whenever a pass defers work to a trigger, it names, at that moment, the agent-run surface that will catch the condition when it fires: a maintained surface a retrieval trigger already resurfaces — a pending port on a pickup surface, a Gaps line, a ripening-region wish — where the team's own cadence will meet the condition; or an active watch — a tending's kept-condition run at its beats, or a mechanical guard — where the condition would fire outside that cadence and no ordinary read would surface it. A deferral left resting on the human remembering to raise the condition is not a deferral but a silent drop: the human gives the deciding word, the judgment, and the attestation, never the vigilance. An arrangement made for a dated reason is a deferral too: the reason's expiry is itself a watched trigger.
