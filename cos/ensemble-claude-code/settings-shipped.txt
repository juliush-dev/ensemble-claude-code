# settings-shipped.txt - the ever-declared settings-path manifest.
#
# The append-only list of every settings.json leaf path this COS has ever
# declared, one dotted path per line. A leaf path runs down to a scalar, an
# array, null, or an empty object. permissions.deny is one path, and so is
# modelSettings.claude-opus-5.effortLevel.
#
# It is merge-settings.py's PRUNE GATE. On a deploy, a path is removed from the
# host's settings.json only when it is listed here AND source settings.json (plus
# the host companion settings.local.json) no longer declares it - a path this COS
# shipped in an earlier release and has since retired. A host key that is NOT
# listed here is one this COS never declared, and the deploy leaves it alone.
# That is the whole point: a host's own keys survive an update.
#
# Maintain it at the moment a path is added - the same moment a new key lands in
# settings.json. Never remove a line: a retired path must stay listed so a future
# update can still prune it from a host that got it. merge-settings.py is
# self-policing here, warning per source-declared path that this file does not
# list; the deploy still proceeds.
#
# LEAF PATHS ONLY. A line must name a leaf - a scalar, an array, null, or an
# empty object - never a parent of one. A line that is a strict ancestor of a
# path the factory declares (permissions, while source declares
# permissions.deny) is not a retired path at all, and executing it would delete
# the host's whole subtree beneath it, permissions.allow and
# additionalDirectories with it. merge-settings.py refuses such a line: it warns
# by name, skips that one prune, and runs the rest. Fix the line rather than
# leaving the warning standing.
#
# Lines beginning with # are comments; blank lines are ignored, and a line is a
# path in full - there are no trailing comments. Keep the file pure ASCII with
# LF line endings, like the deploy scripts that read it.
#
# HONEST INCOMPLETENESS. The seeding below was derived by parsing every committed
# revision of settings.json and unioning the working tree. Version history is a
# LOWER BOUND, not the truth: the deploy reads the working tree, so a key could
# have been deployed to a host and removed again without ever being committed.
# Such a path would linger on that host rather than be pruned. The failure mode
# is a leftover key, never a deleted host key.
#
# COMPANION PATHS ARE NOT LISTED. settings.local.json is host-side and
# gitignored; this is a tracked file. A path only the companion ever declares
# (permissions.additionalDirectories today) is replaced from the companion while
# the companion declares it, and lingers on the host if it is ever dropped from
# the companion entirely. Removing an ENTRY from a companion-declared array does
# take effect: declared paths are replaced whole, never unioned.
#
# Seeded with 14 paths, in the order each was first declared - the append-only
# order a new line continues. One path has ever been retired:
# _provenance. It stays listed forever, so a host that still carries it gets it
# pruned on the next update.
