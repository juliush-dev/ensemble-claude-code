# The Claude Code fixes this COS relies on

The line above names the Claude Code version this COS was last checked against. Run the latest Claude Code: each guard below holds as described only from the version that fixed it.

- 2.1.101 and 2.1.269: two fixes the memory-path deny rules rely on, one making a `permissions.deny` rule win over a PreToolUse hook's `ask` on the same call (the path guard on `Edit|Write` asks on a write outside the session's root), one extending `Edit()` deny rules and the write-path check to the file a Bash `tee` writes.
- 2.1.211: a PreToolUse hook's `ask` on Bash floors the decision at a prompt in auto mode. `hooks/guard-push-gate.sh` and `hooks/guard-herenow.sh` rely on it.
- 2.1.211: nested `.claude/rules` files stay out of a session whose setting sources exclude project settings. The launcher's `--setting-sources user` isolation relies on it. It holds for launcher sessions only; the last entry below covers a session started another way.
- 2.1.214, 2.1.232 and 2.1.285: three PowerShell permission-bypass fixes, one for Windows PowerShell 5.1 sessions, one for `$PSDefaultParameterValues`, one for a command parser that fails to start (the check had skipped deny and ask rules and cached that failure). The PowerShell ask rules on `git push` and on `claude plugin install`, `enable` and `init` rely on them.
- 2.1.216: a resumed background agent session restores the agent's prompt and tool restrictions. A resumed member keeps its card's envelope through it.
- 2.1.251 (documented at 2.1.296): a SessionStart hook on a resumed or forked session that holds a response from Claude receives `seconds_since_last_response`, `context_tokens` and `prompt_cache_likely_expired`. `hooks/refocus.sh` reads the three for its stale-resume line, printed when the cache has likely expired and the context is at least 100,000 tokens; on an older version the fields are absent and it stays silent.
- 2.1.257: a `permissions.ask` rule holds in auto mode inside a compound command or subshell. The `git push` and `claude plugin` ask rules rely on it.
- 2.1.257: hook input carries `scratchpad_dir`. `hooks/guard-scout-bash.sh` anchors to it; without it the guard falls back to the shared scratchpad root.
- 2.1.267: `effort:` frontmatter on subagents applies on models whose default effort is pinned. The Examiner card's `effort:` level relies on it.
- 2.1.280: a write through a symlinked path is judged by where it lands, not by its in-tree spelling. `hooks/guard-archivist-paths.sh` reads paths as written and relies on it for symlinks.
- 2.1.282 (observed there; the version that fixed it is unrecorded): a PreToolUse hook's `ask` on an MCP tool floors the decision at a prompt in auto mode. `hooks/guard-openknowledge.sh` relies on it.
- 2.1.283 (documented there, observed headless; the version that added it is unrecorded): `--append-system-prompt-file` appends a file to the main session's system prompt, interactive or headless, and the text survives compaction; members never receive that prompt. The launchers and `probe-context.ps1` rely on it to give the main session `CONCERTMASTER.md`, the Concertmaster's own rules, and no member.
- 2.1.283 (documented there): SessionStart fires in the main session only; a member gets SubagentStart. `hooks/session-start-cue.sh` relies on it to print `CONCERTMASTER.md` as its fallback into the main session alone.
- 2.1.283 (documented there): a hook's plain stdout is capped at 10,000 characters; above it the model gets a 2,000-character preview and a file path. `fixtures/session-cue/run-fixture.sh` holds the cue's longest print under 9,500.
- 2.1.284 (documented there and again at 2.1.286, in a hooks reference that carries no version; the version that added it is unrecorded): a PreToolUse hook's `deny` reason is shown to Claude, while an `ask` reason reaches only the user. `hooks/guard-openknowledge.sh` relies on it for its denies, each of which names the correction to resend.
- 2.1.287 (documented there): a user-installed mod's `tool.check` hook can approve a call past an ask rule, past a block from a PreToolUse hook outside managed settings, past the auto-mode classifier and, on a host with no managed settings and no Team or Enterprise sign-in, past a deny rule. Every ask rule, deny rule and guard above holds only while no such mod is installed; `claude plugin validate <directory>` lists a plugin's hooks, and `tool.check` or `tool.call` there is the signal. No built-in mod uses either to override a rule or a hook. `hooks/session-start-mod-check.sh` reads the `hooks/hooks.json` of each installed, synced and `skills/` plugin, of each folder `CLAUDE_CODE_PLUGIN_DIRS` names, and of each folder in the session's own project `.claude/skills/` (under the `cwd` its input carries and under `CLAUDE_PROJECT_DIR`), for a `modules` key at every session start and says when one is found. A project one is named as one that may load as `<name>@skills-dir`: the plugin docs load it only once the folder is trusted, and whether it loads under the launcher's `--setting-sources user` is unconfirmed. It cannot see a plugin loaded with the `--plugin-dir` flag, a folder added with `--add-dir`, nor anything installed after the session started.
- 2.1.288 (changelog only; the hooks reference has no sentence for it): a PreToolUse or PermissionRequest hook that matching failed on, or whose tool input could not be serialized to JSON, now blocks the call instead of being skipped. The PreToolUse guards in `settings.json` and `hooks/guard-scout-bash.sh` on the Scout card rely on it for that path. It does not reach a hook that starts and then crashes, times out or exits without a decision, which lets the call continue (hooks reference), nor one that cannot start at all, which this COS records as failing open (the here.now and OpenKnowledge entries in `settings.json`).
- 2.1.289 (changelog only; observed at 2.1.289): `claude plugin validate` no longer skips the plugin when its folder also holds a marketplace manifest, a shape installed plugin copies can carry. The validate signal in the 2.1.287 entry above, the hint `hooks/session-start-mod-check.sh` prints and the command the Operator card's mod stop hands out for an imported bundle (`agents/operator.md`) rely on it; before the fix, such a folder could list no hooks and so show no sign of a mod.
- 2.1.290 and 2.1.296 (changelog only): two Bash permission-check fixes, one making a deny or ask rule catch a command whose name comes from a variable set by a `declare`, `typeset`, `export` or `readonly` prefix, one making a command that assigns `BASH_ARGV0` and then uses it ask instead of auto-approving. The Bash ask rules on `git push` and `claude plugin` rely on them where a name is assembled through a variable, which `hooks/guard-push-gate.sh` does not catch.
- 2.1.296 (observed there; the version that added `claudeMdExcludes` is unrecorded): a session the launcher does not start, such as one T3 Code starts through the Agent SDK, keeps the SDK's default setting sources (user, project and local), so ancestor and nested instruction files would load, the user's own `~/.claude` folder among them. The `claudeMdExcludes` patterns in `settings.json` keep that folder, and the source copy of `always-on/CLAUDE.md` in a clone, out of such a session. Such a session also reads project settings, and the `claudeMdExcludes` lists of all settings layers add up, so a repository keeps its own instruction files out with the same key in its own `.claude/settings.json`. Matching is case-sensitive, so the patterns are case-folded. The Examiner's per-run tests observed it, and so did a live T3 Code session, clean at session start and on a nested read. SDK-hosted sessions' isolation relies on it.
- 2.1.296 (documented there; the version that added it is unrecorded): a PreCompact hook that exits 2 blocks the compaction, and for a manual `/compact` Claude Code shows the hook's stderr to the user; a PreCompact `systemMessage` is discarded. `hooks/refocus.sh` relies on it to stop a manual `/compact` on a conversation idle past its prompt cache at 280,000 tokens or more, and to say why. PreCompact input carries no idle time, so the hook reads the session's transcript, a format Claude Code does not document: the last main-conversation assistant line, its last `timestamp` and its `usage` counts, as written on 2.1.282 and 2.1.296. It fails open, letting the compaction run whenever it cannot read them, so a changed format turns the stop off without a word. One read leans the other way: a `"subtype":"compact_boundary"` line after that assistant line lets the compaction run, because the history was compacted after that line and its size is unknown, so a renamed boundary line would bring back a block quoting the size from before the last compaction.
